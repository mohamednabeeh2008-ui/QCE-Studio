# Contributing to QCE Studio

Thank you for contributing to QCE Studio.

This document defines the contribution workflow for developers, knowledge engineers, reviewers, and maintainers.

---

# Guiding Principles

- Quality over quantity
- Documentation first
- Canonical knowledge first
- Small incremental changes
- Review before merge

---

# Development Workflow

1. Create an Issue.
2. Discuss the proposed change.
3. Create a feature branch.
4. Implement the change.
5. Update documentation.
6. Submit a Pull Request.
7. Complete code review.
8. Merge after approval.

---

# Branch Naming

feature/<feature-name>

fix/<bug-name>

docs/<document-name>

refactor/<module-name>

---

# Commit Messages

Use Conventional Commits.

Examples:

feat: add validation engine

fix: resolve identifier conflict

docs: update architecture

refactor: simplify template manager

---

# Pull Request Requirements

Every Pull Request must:

- Reference an Issue
- Pass validation
- Include documentation updates
- Be reviewed
- Be approved before merge

---

# Coding Standards

- Modular architecture
- Clear naming
- Reusable components
- No duplicated logic
- Unit tests where applicable

---

# Documentation

Documentation is mandatory for:

- New modules
- Architectural changes
- APIs
- Configuration
- Workflows

---

# Code Review Checklist

- Correctness
- Readability
- Maintainability
- Security
- Performance
- Documentation

---

# Community

Contributors are expected to communicate respectfully, collaborate openly, and help maintain the quality of the QCE ecosystem.
